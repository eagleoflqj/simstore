# Releases

## Build identity

Stable tags use `X.Y.Z` without a prefix. `CFBundleShortVersionString` is the nearest stable tag and `CFBundleVersion` is the number of commits since that tag, as reported by `git describe --long`. For example, the `0.1.0` tag produces `0.1.0 (0)` and its twelfth subsequent commit produces `0.1.0 (12)`. The rolling `latest` tag and prerelease tags do not participate in version calculation.

CMake reads the Git version at configuration and stamps the bundle's `Info.plist` on every build, including builds that need no compilation. `SimStoreRevision` is the full source commit SHA, `SimStoreCommitTime` is its Unix timestamp, and `SimStoreSourceDirty` records uncommitted source changes. Unchanged metadata does not rewrite the plist. Full Git history and stable version tags are required. CI uses `fetch-depth: 0` and explicitly runs `git fetch --tags --force` before configuration because the pushed tag can be missing after Actions checkout.

Local builds support dirty source trees. Packaging a release requires a clean source tree and bundle metadata matching the current commit. Stable packaging also requires an exact matching version tag and a commit belonging to `origin/main`.

## Build and publish

The build workflow packages and uploads `SimStore.app.tar.bz2` and `release.json` before running checks. Each is uploaded as a single file without an additional ZIP archive. All checks must pass before publication.

| Event | Result |
| --- | --- |
| Pull request or manual run on another branch | Artifacts only. |
| Push to main or manual run on main | Update tag `latest`, title `Nightly build`, marked as a prerelease. |
| Push of a stable version tag | Create a draft stable release with the version as its title. |
| Publishing a stable release | Refresh `version.json` without rebuilding the app. |

Both publication workflows use the `simstore-releases` concurrency group with a multiple-run queue. Stable drafts can be retried, while an already published stable release cannot have its assets overwritten by the publisher. A delayed build cannot replace a newer nightly. The nightly's package and metadata are uploaded before its version index.

Release descriptions retain the Terminal installation command and the instruction against downloading the archive through a browser. The command uses the release's own tag, including stable tags. Nightly publishing refreshes the index in the same workflow; it does not depend on a second release event generated by `GITHUB_TOKEN`.

To create a stable release, choose the next version and tag the tested main commit:

```sh
git switch main
git pull --ff-only
git tag -a X.Y.Z -m 'Release X.Y.Z'
git push origin X.Y.Z
```

Replace `X.Y.Z` with the release version. Publish the resulting draft in GitHub when it is ready. There is no separate version file or CMake version number to bump. Existing stable tags are preserved.

## Update metadata

Every release has a `release.json` record generated from the actual app and compressed archive:

| Field | Value |
| --- | --- |
| `tag` | `latest` for the rolling nightly, or the stable version tag. |
| `version` | The app's `CFBundleShortVersionString`. |
| `build` | The integer commit count in `CFBundleVersion`. |
| `minOS` | The app's `LSMinimumSystemVersion`. |
| `revision` | The source commit SHA embedded in the app. |
| `time` | The source commit's Unix timestamp. |
| `size` | Archive size in bytes. |
| `sha256` | SHA-256 of the compressed archive. |

`https://github.com/iSimStore/simstore/releases/download/latest/version.json` contains a `versions` array with the current nightly first, followed by all published stable releases in descending numeric version order. Drafts and other prereleases are excluded. Historical minimum OS requirements remain available so a client can choose the newest stable release compatible with its macOS version. Version ordering compares `(version, build)` together; the build count resets at each stable tag.

The index is assembled from release assets rather than a manually maintained history file. Its records contain no download URLs: the repository, tag, and fixed archive name determine the URL. Missing or invalid release metadata fails index generation instead of silently dropping a stable release.

The `Update version index` workflow can also be run manually. To inspect a generated index locally without uploading it:

```sh
python3 scripts/release.py index --repo iSimStore/simstore
```

This writes `build/version.json`. Add `--upload` to publish the file to the `latest` release. Python 3.9 or newer and an authenticated GitHub CLI are required for release administration; building requires Python but does not access GitHub.
